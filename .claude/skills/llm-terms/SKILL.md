# LLM 行业术语表（llm-terms）

维护项目根目录的 `llm-terms.md`：用户每次提供若干 LLM 行业术语，逐个解释并**追加**为术语表中的一行。首次运行创建文件；之后每次追加新术语后，按「排序规则」对全部数据行按生命周期重排，**不改动任何已有行的内容**（唯一例外：「已有行审阅」中经用户确认的调整）。

## 信息来源与真实性（最高优先级）

- 本 SKILL.md **只定义格式与流程，不内置任何术语释义**。所有解释必须由当前会话的 LLM 在运行时基于自身知识生成，禁止从本文件或其他静态来源复制预写内容。
- 对不确定、有争议、新近出现的术语（英文全称、中文译名、领域归属同样适用）：**先用网络搜索核实再写入**；无法核实的，向用户说明并标注「待核实」，不得凭印象编造。
- 拿不准就查，查不到就明说——宁可留空，不可臆造。

## 工作流程

1. 从用户消息中提取本次要解释的术语列表，保持用户给出的顺序。
2. 按「术语校验」逐个检查规范性；有需确认的项时**汇总成一次询问**（AskUserQuestion 或直接提问），待用户答复后再继续，避免多轮打扰。
3. 对照现有表格把本次术语分为两组（大小写不敏感）：表中已有的进入「已有行审阅」，其余为新增；`llm-terms.md` 不存在则先创建（写入一级标题与表头）。
4. 为新增术语逐个按「表格列定义」的七个维度撰写解释，每个术语一行。
5. 按「关联推荐」扫描新行各单元格中引用的、表中尚不存在的术语，汇总成一次多选询问；被选中的一并生成为新行。
6. 用 Edit 在表格末尾（最后一个数据行之后）追加新行；**不改表头、不改动任何已有行的内容**（唯一例外见「已有行审阅」）。
7. 按「排序规则」对全部数据行按生命周期重排（稳定排序，同阶段内保持重排前的相对顺序）。
8. 完成后向用户简短复述：本次新增、已有行调整（如有）与重排后的行序。

## 术语校验（解释前执行）

对用户提供的每个术语先做规范性检查，命中下列情形时**先问后写**：

- **名称不规范**：大小写、拼写、连写或别称与通行写法不符（如 COT、MOE、transfomer）——给出建议的规范名称与理由，询问用户是否接受；接受则「术语」列写规范名，不接受则保留用户原样。
- **名称非英文**：「术语」列一律英文（业内通用缩写或英文全称，见列定义）。用户给中文术语时，建议对应英文规范名并询问确认。
- **疑似非 AI 相关**：与 LLM/机器学习无关的通用词或其他领域术语——明确指出判断依据并建议跳过；用户确认仍要收录时照常收录，并在「所属领域」注明「非 AI（用户确认收录）」。
- 有多个候选规范名、或拿不准是否 AI 相关时，先按「信息来源与真实性」联网核实，再带着依据询问。
- 全部术语均规范且相关 → 不打扰用户，直接进入解释流程。

## 关联推荐（新行写入前执行）

- 撰写新行后，收集其**所有单元格**（相关技术列及场景、做法、原理等列）中引用的、且表中尚不存在的术语。
- 汇总去重后**一次性多选询问**用户是否一并添加（附每个术语的一句话定位与所属阶段）；被选中的按正常流程生成为新行。
- 递归只做一层：因关联推荐新增的行，其自身引用不再触发下一轮推荐，避免无限追问；这些引用留待日后运行时自然扫出。
- 无引用、或引用的术语均已存在 → 不打扰用户。

## 已有行审阅（提交了表中已有术语时）

- 用户提交表中已有术语**不是重复追加**，而是触发对该行的审阅：完整读出原行，检查三件事——信息是否过时、七个维度是否有明显缺漏、与本批新术语的「前置/后续」互链是否缺失。
- 有可改进处：展示原行与**具体修改建议**（改哪个单元格、改成什么、为什么），经用户确认后才应用；这是「不改动已有行」的唯一例外。
- 无可改进处：明确告知「已存在且无需调整」，跳过该术语。

## 排序规则（每次追加后应用）

- 生命周期固定序：**预训练 → 后训练 → 模型推理 → 智能体**。
- 每行取其「所属领域」列中**最早**的阶段作为排序键；横跨多个阶段的术语，按其较早的阶段参与排序。
- 排序必须**稳定**：排序键相同的行保持重排前的相对顺序，新追加的行自然落在同阶段的末尾。
- 重排只移动整行位置，**不修改任何单元格内容**；某行「所属领域」无法解析时，将该行排在最后并向用户说明。

## 表格格式

文件结构固定为：

```markdown
# LLM 行业术语表

| 术语 | 英文全称 | 中文全称 | 所属领域 | 应用场景与解决的问题 | 具体做法 | 底层原理 | 相关技术（前置 / 后续） |
|------|----------|----------|----------|----------------------|----------|----------|--------------------------|
| ...  | ...      | ...      | ...      | ...                  | ...      | ...      | ...                      |
```

### 列定义（七个解释维度）

| 列 | 写法要求 |
|----|----------|
| 术语 | **一律英文**：业内以缩写形式通行的用缩写（如 MoE、RLHF、DPO、KV Cache）；否则用英文全称（如 Self-Supervised Learning、Knowledge Graph、Reward Hacking）；没有通行缩写的词不生造或挪用缩写（如 SSL、AE、KG 这类歧义缩写不用）。用户给中文名或其他写法时，经「术语校验」确认英文规范名后写入 |
| 英文全称 | 展开后的英文名，实词首字母大写 |
| 中文全称 | 通行的中文译名 |
| 所属领域 | 从「预训练、后训练、模型推理、智能体」中选，可多选，按生命周期顺序用「、」连接 |
| 应用场景与解决的问题 | 该技术用在哪、没有它会怎样，1–2 句 |
| 具体做法 | 工程上具体怎么实现或怎么用，1–3 句 |
| 底层原理 | 数学或机制层面为什么有效，1–3 句 |
| 相关技术（前置 / 后续） | 固定格式「前置：A、B；后续：C、D」 |

### 单元格书写约定

- 单元格内**禁止出现竖线 `|`**（会破坏表格）；并列用「、」，分层用「；」或 `<br>`。
- 中文书写，术语与缩写保留英文原文。
- 每格 1–3 句，先结论后细节；归属或译名存在争议时注明「（存在争议）」，不要硬猜。

### 所属领域判定口径

- **预训练**：在大规模语料上的初始训练（架构、训练目标、数据配比等）
- **后训练**：预训练之后的对齐与能力注入（SFT、RLHF/RLAIF、DPO 等）
- **模型推理**：部署与解码阶段（量化、KV Cache、采样策略、投机解码等）
- **智能体**：模型作为自主主体的工具调用、规划、记忆与多智能体协作

## 行格式占位（仅示意列顺序，内容运行时生成）

| （术语） | （英文全称） | （中文全称） | （预训练、…） | （1–2 句） | （1–3 句） | （1–3 句） | 前置：A、B；后续：C、D |
